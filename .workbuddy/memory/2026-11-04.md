## 指法提示改为「整串推进」，字边界不再是终点

问题：打完一个字的拼音后提示停住，必须按空格把这个字上屏，下一个字母才亮。

原因（两处都把范围钳在「当前字」）：
- `renderAnswer()` 里 `nxLimit = pre[typed.length + 1]`，拼音行的 `.nx` 走不出当前字；
- `hintState()` 的 `target` 只取 `pinyinAlign(...)[typed]` 单个字，敲全就返回 `done`，
  键盘高亮、手部图层、状态栏一起停。

改法：
- 新增 `restPinyin()`：从当前字起把剩余所有字的拼音接成一整条（`ü`→`v`，去非字母）。
- `hintState()` 用整串做前缀匹配，返回 `{letter, done, full}`：还有字母就 `letter`，
  整串敲完 `done=true`（空格高亮），答案已全部上屏 `full=true`（提示 Enter 提交）。
- `renderAnswer()` 的 `nxLimit` 改成 `pre[chars.length]`，`.nx` 可跨字推进。
- `updateHint()` 用指纹 `code + done/full` 判变化（原来只比 `code`，导致 done 态文案不刷新）；
  `done` 时把 `Space` 键加 `.is-hint`，`FINGER_MAP['Space']='thumb'` 自动让右手拇指压到空格层。
- 状态栏：`下一个 x · 手指` / `字母已敲完 · 空格上屏` / `Enter 提交`。

实测（`_data/re/hint.js`，CDP + `Input.imeSetComposition` 模拟真实组词）：
- 放弃：f→a→n→g→q→i 一路推进，`fang` 之后 nx 落到第二字的 `q`（跨字成立），
  敲完 `fangqi` 空格键高亮 + 右手拇指压空格 + 状态栏「字母已敲完 · 空格上屏」。
- 图书馆（三字）：跨两个字边界，末了同样落到空格。
- 考虑：拼音行显示 `ü`，提示 `KeyV`。
- 先上屏一个字（`text:放`）后剩余串重算为 `qi`，提示仍指向 `q`；整串上屏后转「Enter 提交」。
- 敲错（`fangx`）时提示仍指向该位的 `q`；深色主题下空格高亮清晰。

保持不改的：输入法本身仍是真实 IME，能不能一次上屏整词取决于它自己的候选；
提示层只保证「不断流」，中途断词时按空格上一组也能接着走。

## 自评前置：先选「忘了 / 模糊 / 很熟」，再揭晓中文

需求：三个记忆程度选项要在翻译出现之前就摆在眼前，选完才跳中文释义。

## 键盘常驻 + 分阶段操作提示

需求：键盘一直显示，并且始终提示「现在该按什么」（敲完意思后 Enter 高亮）。

改动：
- `hintState()` 重写成状态机，返回 `{codes, text, hand}`：
  ① recall → `['KeyJ','KeyK','KeyL']`「选择记忆程度」；
  ② typing 且 `state.locked` → `['Backspace']`「打错了 · Backspace 删掉重来」；
  ③ 全部字已上屏 → `['Enter']`「答案已输入完 · Enter 提交」；
  ④ 拼音敲完 → `['Space']`；⑤ 否则逐个字母（含手指名）。
  `hand` 只取一个键给手部图层，Enter/Space 有预画层，Backspace 没有 → 退回 neutral。
- `updateHint()` 改成支持多键高亮，指纹 `codes.join(',')+|+text`（原来单键指纹，多键会漏刷）。
- `loadWord()` 不再 `showKeyboard(false)`，改为常驻 `true`；`setView()` 按视图开关
  （统计/词库收起、回学习区恢复并 `updateHint()`）。
- 导航「学习」：已有 `state.current` 时只 `setView('drill')`，不再 `loadNext()`，
  否则从统计页回来会丢掉敲了一半的词。
- `.drill.is-recall .meaning-block{display:none}`：自评阶段没有答案，收起答案区，
  单词和三个选项聚在一起，不留大片空白。

布局（关键）：键盘常驻后会顶出折叠线，必须压学习卡：
`@media(min-width:861px)` 下 `.drill.kb-open .study-shell{min-height:360px}` + stage/word/
meaning/action 全面压缩；矮屏断点从 `max-height:800` 提到 `860`（801~860 这段原来会溢出），
矮屏 `.drill.kb-open .study-shell{min-height:320px}`、dock 196、键高 25、kb-wrap 72%。
实测 1440×{1000,900,860,820,780} 均 `scrollHeight === innerHeight`，一屏放下。

验证：自评 `hint=KeyJ`、双手 neutral；打字 `KeyF` + `hb-f`；敲完 `Space` + `hb-space`；
答案上屏 `Enter` + `hb-enter`；多打一个字 `Backspace`。指尖与键位仍对齐（高亮指 stroke 顶边

## 20:55 修复「手部引导图偏移」（分支 fix/hands-anchor → 已并入 feat/layout-fill-viewport 第 2 个提交 21b6d29）

现象：手指图整体向右上方偏移，指尖压在键盘外。
根因：不是 left/top 写错，而是**键帽是 71×38 的扁键**。手部素材的画布列距 30.2、行距 28.9
（SVG 单位），比例 ≈1.06；扁键的行/列比例 1.87，等比缩放不可能横竖同时对上。
旧的 `translateX(6.7%) scale(1.587)` 只是针对 664px 键盘手调的经验值，键盘一加宽就失效。

做法：
- `.kb-key{aspect-ratio:1.05}`（1.05 = 30.2/28.9 反推），键高由键宽推导，不再写死 px
- `.kb-board` 改 `grid + grid-auto-rows:1fr`，否则最下一排全是宽键会塌成一条
- shift 权重 2.2→2.6，字母行与数字行等宽（否则该行键宽 +5%，行高被它撑大）
- 矮屏不再单独改键高，改 `.keyboard-panel{--kb-w}` 收窄面板等比缩小
- `.hands` 盒子固定 716.3×380、`transform-origin:0 0`，位置由 `fitHands()` 算
- `fitHands()`：8 个主键指尖坐标（量自 SVG `.st5` 笔迹顶点）+ 真实键心做最小二乘，
  解等比 s 与平移 tx/ty 写入 transform；resize / ResizeObserver 重算；残差 ≤12px
- 手腕淡出终点按缩放反算百分比，面板底部留 34px 掌托，避免硬切

验证：1440×900 / 1920×1080 / 1280×800 / 1280×680 均 `scrollHeight==innerHeight`；
键帽恒为 1.05:1；按 F/J、D/K 截图确认指尖落在对应键上（偏差约 10px，约 1/7 键宽）。

# 2026-11-04

## 指法提示改为「整串推进」，字边界不再是终点

问题：打完一个字的拼音后提示停住，必须按空格把这个字上屏，下一个字母才亮。

原因（两处都把范围钳在「当前字」）：
- `renderAnswer()` 里 `nxLimit = pre[typed.length + 1]`，拼音行的 `.nx` 走不出当前字；
- `hintState()` 的 `target` 只取 `pinyinAlign(...)[typed]` 单个字，敲全就返回 `done`，
  键盘高亮、手部图层、状态栏一起停。

改法：
- 新增 `restPinyin()`：从当前字起把剩余所有字的拼音接成一整条（`ü`→`v`，去非字母）。
- `hintState()` 用整串做前缀匹配，返回 `{letter, done, full}`：还有字母就 `letter`，
  整串敲完 `done=true`（空格高亮），答案已全部上屏 `full=true`（提示 Enter 提交）。
- `renderAnswer()` 的 `nxLimit` 改成 `pre[chars.length]`，`.nx` 可跨字推进。
- `updateHint()` 用指纹 `code + done/full` 判变化（原来只比 `code`，导致 done 态文案不刷新）；
  `done` 时把 `Space` 键加 `.is-hint`，`FINGER_MAP['Space']='thumb'` 自动让右手拇指压到空格层。
- 状态栏：`下一个 x · 手指` / `字母已敲完 · 空格上屏` / `Enter 提交`。

实测（`_data/re/hint.js`，CDP + `Input.imeSetComposition` 模拟真实组词）：
- 放弃：f→a→n→g→q→i 一路推进，`fang` 之后 nx 落到第二字的 `q`（跨字成立），
  敲完 `fangqi` 空格键高亮 + 右手拇指压空格 + 状态栏「字母已敲完 · 空格上屏」。
- 图书馆（三字）：跨两个字边界，末了同样落到空格。
- 考虑：拼音行显示 `ü`，提示 `KeyV`。
- 先上屏一个字（`text:放`）后剩余串重算为 `qi`，提示仍指向 `q`；整串上屏后转「Enter 提交」。
- 敲错（`fangx`）时提示仍指向该位的 `q`；深色主题下空格高亮清晰。

保持不改的：输入法本身仍是真实 IME，能不能一次上屏整词取决于它自己的候选；
提示层只保证「不断流」，中途断词时按空格上一组也能接着走。

## 自评前置：先选「忘了 / 模糊 / 很熟」，再揭晓中文

需求：三个记忆程度选项要在翻译出现之前就摆在眼前，选完才跳中文释义。

改动（`assets/app.js`）：
- `loadWord()`：`rateRow` 直接 `add('show')`，`stageMode` 改「看词自评」；
  `hintText()` 三个分支的提示从「空格 揭示中文」换成 `J 忘了 · K 模糊 · L 很熟`。
- `rate(g)`：guard 从 `phase !== 'rate'` 改为 `'recall'`，内部补 `fullDef.classList.add('show')`，
  即「评级 = 揭晓」。
- 删除 `reveal()` 与「点击卡片任意处揭示」的 handler；空格/Enter 不再揭示，
  `document` 的 keydown 只保留 recall 阶段的 J/K/L（含 1/2/3）与 R 重听。
- `renderAnswer()`：`masked` 阶段直接 `host.innerHTML = ''`。原来渲染的空 `.mask` 灰块会
  泄露答案字数，自评时不该出现；顺带删掉 forEach 里的 masked 分支。

验证（`_data/re/hint.js` 扩了 `probe` / `enter` / `clickrate:N` 步骤）：
初始 `rateShown=true, defShown=false, typeShown=false`；点「模糊」后反转并出现拼音与输入行；
输入答案 + Enter 提交后进入下一词，又回到自评态。整页截图确认自评时答案区完全空白。


## 键盘常驻 + 分阶段操作提示

需求：键盘一直显示，并且始终提示「现在该按什么」（敲完意思后 Enter 高亮）。

改动：
- `hintState()` 重写成状态机，返回 `{codes, text, hand}`：
  ① recall → `['KeyJ','KeyK','KeyL']`「选择记忆程度」；
  ② typing 且 `state.locked` → `['Backspace']`「打错了 · Backspace 删掉重来」；
  ③ 全部字已上屏 → `['Enter']`「答案已输入完 · Enter 提交」；
  ④ 拼音敲完 → `['Space']`；⑤ 否则逐个字母（含手指名）。
  `hand` 只取一个键给手部图层，Enter/Space 有预画层，Backspace 没有 → 退回 neutral。
- `updateHint()` 改成支持多键高亮，指纹 `codes.join(',')+|+text`（原来单键指纹，多键会漏刷）。
- `loadWord()` 不再 `showKeyboard(false)`，改为常驻 `true`；`setView()` 按视图开关
  （统计/词库收起、回学习区恢复并 `updateHint()`）。
- 导航「学习」：已有 `state.current` 时只 `setView('drill')`，不再 `loadNext()`，
  否则从统计页回来会丢掉敲了一半的词。
- `.drill.is-recall .meaning-block{display:none}`：自评阶段没有答案，收起答案区，
  单词和三个选项聚在一起，不留大片空白。

布局（关键）：键盘常驻后会顶出折叠线，必须压学习卡：
`@media(min-width:861px)` 下 `.drill.kb-open .study-shell{min-height:360px}` + stage/word/
meaning/action 全面压缩；矮屏断点从 `max-height:800` 提到 `860`（801~860 这段原来会溢出），
矮屏 `.drill.kb-open .study-shell{min-height:320px}`、dock 196、键高 25、kb-wrap 72%。
实测 1440×{1000,900,860,820,780} 均 `scrollHeight === innerHeight`，一屏放下。

验证：自评 `hint=KeyJ`、双手 neutral；打字 `KeyF` + `hb-f`；敲完 `Space` + `hb-space`；
答案上屏 `Enter` + `hb-enter`；多打一个字 `Backspace`。指尖与键位仍对齐（高亮指 stroke 顶边
落在键高 40%~55% 处）。深色下给 `.kb-key.is-hint` 加淡蓝底，否则三个键在暗色键面上认不出来。

## 练习页锁定一屏（卡片收小，去掉上下滚动）

问题：视口高度 ≤720 时页面溢出（1280x720 溢 16、1024x640 溢 74）。根因是
`.study-shell` 有 min-height，且 stage 的内容高度把整列顶出视口。

改法（`assets/style.css`，全部收在 `@media (min-width:861px)` 内）：
- `.drill { height: calc(100dvh - 72px); min-height:0; overflow:hidden; padding:20px 24px 10px }`
  —— 顶栏固定 72，所以 72 + drill 高度 = 100vh，页面永远不会出现纵向滚动。
- `.study-shell{min-height:0}`（原 600）、`.stage{min-height:0; padding:10px 30px 6px}`、
  `.drill-top{min-height:48px}`（原 64）。
- `.word{font-size:clamp(34px, min(5.4vw, 7.6vh), 72px)}`：把 vh 放进 clamp，
  矮屏自动缩，大屏封顶 72。`.answer{min-height:1.9em}`、`.meaning-block{min-height:0}`、
  `.action-zone{height:78px}`。
- 断点：`max-height:860` 键高 25 / kb-wrap 72% / word 7.2vh；新增 `max-height:700`
  再压一档（键高 22、kb-wrap 66%、word 6.8vh、answer 字号下调、action 70）。
- 自评态（is-recall）意义区本来就 display:none，内容仍在 stage 里垂直居中。

验证：`_data/re/measure.js`（新脚本，W/H 环境变量，输出 scrollHeight/各块矩形/board/lastRow）。
1920x1080、1440x900、1440x768、1366x768、1280x720、1024x640、1280x600 全部
`scrollHeight == innerHeight`；键盘最后一排在面板内（1440x768：board 751 < panel 758）。
手机（390x844）不锁高度、键盘仍隐藏；统计/词库/完成页不受影响。

## 切词上下跳动修复（练习页）
现象：每次切到下一个词，卡片内容整体位移，键盘区看着被压。实测（1440x900）：
看词态 word top=278，自评后打字态 224 —— `.drill.is-recall .meaning-block{display:none}`
把 112px 的释义区整块摘出文档流，舞台 `justify-content:center` 随之重算，
单词瞬移 54px；`inp.focus()` 还可能触发隐式滚动；矮屏下 `.action-zone` 被 flex
压到 35px、`.hints` 换行都会挤卡片。

修法（c2cd325）：
- `.drill.is-recall .meaning-block{visibility:hidden}` 保留占位，两个阶段舞台内容
  等高 → 单词位置恒定；删掉 `.drill.is-recall .action-zone{margin-top:8px}`。
- 桌面端 `.meaning-block{height:var(--meaning-h); overflow-y:auto}`，
  `--meaning-h: clamp(104px,16vh,150px)`（矮屏档 132/118/64），长释义框内滚。
- `.action-zone/.drill-top/.phonetic-row/.hints` 全部 `flex:0 0 auto`；
  `.stage{overflow:hidden}` 只在卡片内消化溢出。
- `setView` 给 html/body 加 `is-drill-locked`（仅 min-width:861px 生效，
  overflow:hidden），`inp.focus({preventScroll:true})`。
- 新增 `max-height:620px` 档：word 更小、`--meaning-h:64px`、`.full-def` 隐藏。

回归脚本 `_data/re/poscheck.js`（14 档 1920x1080~900x560）：断言三态 word top
一致、scrollY=0、文档无溢出、面板底 < vh、操作区高度 ≥60px。全部通过。
另 `_data/re/keyflow.js` 走真实按键（J→插入中文→Enter）确认输入/切词无回归；
`_data/re/dockcheck.js` 确认键盘行都在面板内；390x844 移动端未受影响。

## 全站一屏：任何视图都不出现页面级滚动
诉求：整个站点（学习/统计/词库/完成）都要一屏装下，不上下滚动。
实测原状（_data/re/viewcheck.js，11 档尺寸）：
- drill 已 0 溢出（上一轮成果）；stats 在 ≤900 高时溢出 71~371px；
- words 因为一次性渲染 200 行词表，文档高度 10624px，必然滚动。

改法：
- `@media(min-width:861px)` 下 html/body `height:100%; overflow:hidden`，
  `.main` 固定 `100dvh-72px`；stats/words/done 视图 `display:flex;height:100%`。
- 统计页：两张图包进 `.chart-row`（flex 列，各 `flex:1 1 0`），标题/卡片定高；
  `renderChart` 按宿主 `clientWidth/clientHeight` 生成 viewBox（原来写死 640x150，
  一屏布局下会被拉伸），`window.resize` 防抖重绘。
  窗口 ≤620px 高时 `.chart-row` 转 `row`，两图并排换回可读高度。
  窄图 X 轴末尾刻度会与前一个重叠，标签下标改为先收集再剔除（<42px 就只留最后一天）。
- 词库页：表格卡片 `flex:1;min-height:0;overflow-y:auto`，表头 `position:sticky`；
  滚到底自动续下一批（原「显示更多」保留）；导入区改成可折叠（`.import-toggle`），
  高屏默认展开、矮屏默认收起，把行数让给词表。
- 完成页 `.done` 高度收敛到 100%。

回归：viewcheck 44 项（4 视图 × 11 档 1920x1080~1024x480）全绿、donecheck 8 项
（含横向溢出）全绿、wordflow 验证搜索/自动加载/表头吸顶/折叠、poscheck 14 档
学习页切词仍稳定、390x844 等移动端（<861 不锁）保持自然滚动、fontScale 1.1 12 项全绿。

## 三档自评 → 复习权重（借鉴 TypeWords/FSRS 的思路，自研轻量版）
需求：忘了=hard、模糊=good、很熟=easy；hard 复现明显提升，good 比 hard 少 10%，
easy 极少再出现。参考仓库 E:/项目A/英语单词背诵github（TypeWords，Nuxt+Pinia，
FSRS 在 app/core/hooks/fsrs.ts）。

实现（assets/app.js，仍是不引入依赖的 ES5 风格）：
- 新增常量表 `GRADE_WEIGHT = {1:1, 2:0.9, 3:0.03}`、`GRADE_FIRST_GAP = {1:2min, 2:10min}`、
  `EASY_IV_MULT = 1.6`；记录结构加 `grade` 字段（load() 用 `r.last` 迁移旧数据）。
- `applyGrade()` 写 `rec.grade`；easy 的 SM-2 首档从 1 天抬到 3 天、次档 7 天、之后 ×ease×1.6。
- 新增 `reviewWeight()`：档位权重 × 逾期加速（每逾期 1 小时 +1 倍，封顶 7 倍）。
- 新增 `pickWeighted()`：轮盘赌随机；`pickNext()` 里原本 `due[0]` 改为 `pickWeighted(due)`。
- `scheduleRetry` 的模糊档从 11~14 收紧到 5~7，与 1:0.9 的差距对齐（本轮内不吃亏）。
- `window.__drillRev` 暴露权重与抽取，供回归脚本统计。

实测（_data/re/probcheck.js，300 词同逾期、抽样 60000 次）：
hard 51.71% / good 46.69% / easy 1.60%，good÷hard = 0.903。
_data/re/gradecheck.js 走真实按键：忘→grade1/2min，模糊→grade2/10min，很熟→grade3/3天，全部通过。
poscheck（14 档切词）、keyflow、viewcheck 无回归。
